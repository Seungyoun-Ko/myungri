# 인설명리 Android 앱 업데이트 안내서 (웹 v1.4.2 → 앱 반영)

작성일: 2026-10-23
대상: Android 앱 **인설명리 1.06** (versionCode 7, 계산 기준 `KR-2026.10-4`)
기준: 웹앱 **v1.4.2** (app.inseol.com, 계산 기준 `KR-2026.10-7`)

이 문서는 **앱을 작업하는 새 대화창**에서 읽고 바로 시작할 수 있도록 만든 인수인계 문서입니다.
웹앱은 앱 1.06의 기획서를 바탕으로 만들었고, 그 뒤 v1.0 ~ v1.4.2까지 계산 규칙과 풀이가 많이 바뀌었습니다. 이제 반대로 **앱이 웹을 따라잡을 차례**입니다.

> 가장 중요한 원칙: **같은 사람을 앱과 웹에서 봤을 때 결과가 같아야 합니다.** 5장의 기준 답안(`reference-cases.json`)으로 반드시 대조하세요.

## 1. 진행 방식 고르기 (먼저 결정)

웹의 풀이 문장은 한국어·영어 합쳐 1MB가 넘고, 규칙도 많이 바뀌었습니다. 세 가지 길이 있습니다.

| 방식 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A. Kotlin으로 다시 옮기기** | 바뀐 계산 규칙과 풀이를 앱 코드에 하나씩 이식 | 앱 구조 그대로 | 작업량이 가장 큼. 웹이 바뀔 때마다 또 옮겨야 해서 결과가 어긋나기 쉬움 |
| **B. 웹 계산·풀이 JS를 앱에 넣기 (권장)** | 웹 `src/engine/`을 JS 파일 하나로 묶어 앱 `assets/`에 넣고, 앱이 지금 `saju_engine.html`을 부르듯 WebView(또는 JS 엔진)로 불러 결과 JSON을 받음. 화면은 앱이 그림 | 계산·풀이가 웹과 **항상 같음**. 웹을 고치면 파일만 바꿔 넣으면 됨 | 묶음 빌드 설정이 한 번 필요. 자미두수가 Kotlin 계산에서 JS로 바뀜 |
| **C. 앱 화면을 웹으로 (TWA/WebView)** | 앱이 웹앱 화면을 그대로 띄움 | 가장 빠름 | AdSense 광고는 앱 WebView 안에서 쓸 수 없음(AdMob로 따로 붙여야 함). 앱다운 느낌이 줄고, 스토어 심사에서 "웹사이트 포장 앱"으로 보일 위험 |

**권장은 B입니다.** 앱의 사주 계산은 이미 WebView 안의 JS(`saju_engine.html` + `lunar.js`)로 돌아가므로, 같은 자리에 웹 엔진 묶음을 넣는 것이 자연스럽습니다.

B를 고르면:
1. 웹 저장소에서 엔진 묶음을 만듭니다(예: Vite 라이브러리 빌드로 `inseol-engine.js` 하나, 전역 `InseolEngine` 노출).
   - 노출할 함수 예: `compute(input)` → 사주·명반 결과 JSON, `reading(input, lang)` → 풀이 섹션 JSON, `match(a, b)`, `today(input, date)`.
   - 웹 저장소에 이 빌드 설정을 넣는 일은 **웹 쪽 대화창에 요청**하는 것이 깔끔합니다(웹 저장소는 웹 대화창이 관리).
2. 앱은 `EngineBridge`에서 새 묶음을 불러 결과 JSON을 받아 기존 화면 모델로 바꿉니다.
3. 자미두수는 Kotlin `JamidusuCalculator` 대신 JS 결과를 쓰거나, Kotlin을 유지한다면 2장의 자미두수 변경을 이식하고 기준 답안으로 대조합니다.

## 2. 계산 변경 (반드시 맞출 것)

계산 기준은 `KR-2026.10-4`(앱 1.06) → `-5`(웹 v1.0.1) → `-6`(v1.1) → `-7`(v1.2)으로 올라갔습니다. 앱도 다 맞춘 뒤 `KR-2026.10-7`로 올리고, 보관함의 예전 결과에는 "현재 기준으로 새로 계산" 안내를 띄우세요.

### 2.1 기둥·대운 (v1.0.1, 기준 -5)
- **대운 시작 해 = 출생 해 + 대운수**(연 나이 기준). 예전에는 시작 나이와 시작 해가 1년씩 어긋나는 경우가 있었습니다(예: 1978년생 "40~49세 · 2017~2026년").
- **격국 이름**: 음간(乙·丁·己·辛·癸) 일간에 월지가 겁재면 **월겁격**. 양간이면 예전처럼 양인격.
- **출생시간 칸은 비어 있게**: 12:00이 미리 채워져 있으면 시간 모르는 사람이 오시로 계산됩니다. 시간을 넣거나 '모름'을 골라야 결과를 보게 합니다.

### 2.2 강약·용신 (v1.1, 기준 -6) — 결과가 가장 많이 바뀌는 부분
- **지지는 지장간 비율로 나눠 셉니다**(통근 반영).
  - 지장간이 셋이면 여기 10% · 중기 30% · 본기 60%, 둘이면 여기 30% · 본기 70%.
  - 자리 가중치: 천간 모두 10, 지지는 년 10 · 월 30 · 일 20 · 시 10.
- **강약 점수** = (비겁 + 인성 비율) − (식상 + 재성 + 관성 비율), 일간 제외, −100 ~ 100.
- **강약 경계**: 극강 ≥ 40, 신강 ≥ 12, 중화 > −22, 신약 > −80, 그 아래 극약.
  - 극약이면 격국 옆에 "(종격 후보)", 극강이면 "(전왕격 후보)".
- **용신·희신·기신·구신**: 먼저 강약 방향으로 '도움 쪽'과 '부담 쪽'을 나눈 뒤 그 안에서 고릅니다.
  - 점수 ≥ 0(강함): 도움 = 식상·재성·관성, 부담 = 비겁·인성
  - 점수 < 0(약함): 도움 = 비겁·인성, 부담 = 식상·재성·관성
  - 용신 = 도움 쪽에서 가장 적은 기운
  - 희신 = 도움 쪽에서 용신을 생하는 기운 → 없으면 용신이 생하는 기운 → 없으면 남은 도움 기운
  - 기신 = 부담 쪽에서 용신을 극하는 기운 → 없으면 부담 쪽에서 가장 많은 기운
  - 구신 = 부담 쪽에서 기신을 생하는 기운 → 없으면 남은 부담 기운
  - 정확한 코드는 `saju.ts`의 `yongsinOf`를 그대로 따르세요.

### 2.3 자시·윤달 (v1.1, 사주·자미두수 공통)
- **자시 기본 = 다음 날**(밤 11시대 출생은 다음 날 일주). 입력에 '당일로(야자시)' 옵션(23시·0시 입력 때만 표시).
  - 예전 앱은 사주는 다음 날, 명반은 당일로 서로 달랐습니다. **이제 둘 다 같은 기준**입니다.
- **자미두수 윤달 기본 = 15일까지 그달, 16일부터 다음 달**. 옵션으로 '같은 달·다음 달'.
- 결과 화면에 어느 기준을 썼는지 한 줄 안내.

### 2.4 운의 좋고 나쁨 (v1.1 ~ v1.2, 기준 -7)
- **기운 점수**(`elementFavor`): 용신·희신 +1, 기신·구신 −1, 나머지 도움 쪽 +0.5, 나머지 부담 쪽 −0.5(늘 0이던 기운을 없앰).
- **운 점수**(`fortuneScore`): 천간 점수와 지지 점수를 섞습니다.
  - 지지는 지장간 비율(60·30·10)로 나눠 점수를 냅니다.
  - 세운·월운은 지지 비중 0.5, **대운은 0.6**.
  - 운의 지지가 원국 지지 둘과 **삼합**을 이루면 그 기운 점수를 더합니다(`shinsal.ts`의 `triadWithChart`).

### 2.5 해외 출생 (v1.0)
- 해외 도시 약 100곳. 시간대는 IANA 자료로 그 시각의 UTC 오프셋과 서머타임을 계산합니다(Android는 `java.time.ZoneId`로 같은 일을 할 수 있음).
- 서머타임 시작으로 없는 시각은 입력을 막고, 끝나서 두 번 있는 시각은 앞/뒤를 고르게 합니다.
- 절기(년·월주)와 대운 시작 나이는 실제 출생 순간 기준, 시주·일주는 도시 경도 기준 현지 태양시(옵션으로 현지 표준시).
- 남반구 출생에는 계절 문장을 넣지 않습니다.
- 한국 도시는 예전과 똑같이 한국 시각 규칙을 씁니다.

### 2.6 자미두수 표 (확인 필요)
- 웹의 묘왕리함 표는 iztro(MIT) 표를 바탕으로 했고, 태양 유궁만 앱 사례(함)에 맞췄습니다.
- 잡성 35개, 천괴·천월, 화성·영성 배치는 일반적인 표를 씁니다.
- **앱 표와 다른 칸이 있으면 알려 주세요.** 어느 쪽을 기준으로 할지 정해서 웹과 앱을 함께 맞춥니다.

## 3. 풀이 변경

웹 풀이는 앱 1.06의 `Tongbyeon.kt`보다 훨씬 커졌습니다. B 방식이면 아래가 저절로 따라옵니다.

- **쉬운 말 원칙**: 본문에 전문 용어·한자 없이 쓰고, 용어는 항목마다 "명리 근거 보기"에만 모읍니다.
- **사주 7항목**: 나는 어떤 사람 · 성격 · 일과 적성 · 연애 · 결혼 · 재물 · 건강 · 사람 관계.
- **운**: 10년 운(대운) 풀이와 인생 흐름 그래프, 한 해 운세(분야별 + 12달, 같은 문장 반복 없음).
- **모순 거르기**: 서로 반대인 성향 문장이 함께 나오지 않게 태그로 거릅니다(`reading/tags.ts`, `conflict.ts`).
- **조후**: 『궁통보감』 요약 120칸, "태어난 계절로 보면…" 문장.
- **구조 풀이 14종**: 관살혼잡, 재다신약, 식신제살 등(최대 2개).
- **신살·지지 관계**: 공망, 역마·도화·화개(삼합 기준), 천을·문창귀인, 양인, 백호, 괴강, 삼합·방합·형·파·해·원진.
- **자미두수**: 12자리 전부, 쌍성 조합 24종, 명반 격국 14종, 육친 자리 전용 문장, 밝기 3단계 보정, 차성 안내, 사화 겹침 묶기, 명주·신주, 궁간 사화(자화), 대한·유년 두 층 표시.
- **종합 풀이**: 사주와 자미두수를 함께 읽음.
- **영어**: 모든 풀이에 영어판이 있습니다(원어민 편집 검수). 앱을 영어로도 내려면 그대로 쓸 수 있습니다.

### 4.1 카카오톡 공유를 앱에 붙일 때

- 콘솔의 [플랫폼] → **Android 등록**: 패키지명 `com.lifedesign.inseolmyeongri`, **키 해시**(디버그 키, 업로드 키, **Play 앱 서명 키** 세 가지 모두).
- Kakao Android SDK의 `ShareClient.instance.shareDefault(...)`로 피드 메시지를 보냅니다. 웹과 같은 내용으로:
  - 제목: `🐲 나는 '흰 용' · 경진일주` (띠 동물 이모지: 🐭🐮🐯🐰🐲🐍🐴🐑🐵🐔🐶🐷, 지지 순서)
  - 설명: `{한 줄 은유} (MBTI로 치면 ISTP)` 예: "대장간의 무쇠처럼, 두드릴수록 쓸모 있는 칼이 되는 사람 (MBTI로 치면 ISTP)"
  - 그림: `https://app.inseol.com/og.png` (1200×630)
  - 버튼: '나도 내 사주 보기' → `https://app.inseol.com/`, '우리 궁합 보기' → `https://app.inseol.com/#/match?a=<s>-<b>`
  - 궁합 초대: 제목 `'흰 용'의 궁합 초대가 왔어요`, 설명 "생년월일만 넣으면 우리 둘의 궁합을 쉬운 말로 풀어 줘요. 생년월일은 서버로 보내지 않아요."
- 카카오톡이 없으면 Android 공유 시트(`Intent.ACTION_SEND`)로 링크를 보냅니다.
- **REST API 키·Admin 키는 앱에 넣지 마세요**(대화창에도 붙여 넣지 마세요).
- 로고: 웹 `web/public/brand/inseol-logo-*.png`(도장 로고, 1024·512·128px, 투명 1024px).
